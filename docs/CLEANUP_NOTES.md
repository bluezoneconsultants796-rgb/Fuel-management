# Cleanup & fix log

Changes made when consolidating the original upload into this project.

## Removed (duplicates / leftovers)
- `backend/dist/` — compiled build output (regenerated by `npm run build`).
- `backend/src/models/*` — four leftover **Mongoose** models; the app uses Prisma. Their only
  live use was a few constants, now imported from `src/types/domain.ts`.
- `backend/src/utils/regex.ts` — unused.
- `mongoose` dependency — no longer used.
- `backend/prisma/migration_lock.toml` — stray duplicate (the real one is in `migrations/`).
- `mobile/src.zip` — an older copy of `mobile/src`.
- `mobile/.expo/` — local Expo cache.
- `backend/uploads/sample-slip-*.png` — regenerated by `npm run seed`.
- All `.env` files — contained a live database password (see Security).

## Bugs fixed
1. **Validators rejected every real ID.** Zod schemas required 24-char MongoDB ObjectIds, but
   IDs are UUIDs, so any request carrying `driverId`/`vehicleId`/`assignedVehicleId`/… failed.
   Now one shared `validators/common.ts` UUID validator.
2. **Migration drift.** `fuelType` was the only column without `@map`, which led to a
   destructive second migration (drop `fuel_type`, add NOT NULL `fuelType`) that fails on any
   table with data. Schema now maps it to `fuel_type`; the patch migration is gone and the
   `init` migration matches the schema exactly.
3. **Mobile: PDF download broken** — `expo-file-system` v57 moved `cacheDirectory` /
   `downloadAsync` to `expo-file-system/legacy`.
4. **Mobile: runtime crash** — `Pressable` used but not imported in `FuelRecordsScreen`.
5. **Mobile: `npm run typecheck` failed everywhere** — React 19 removed the global `JSX`
   namespace (now `React.JSX.Element`); plus a missing `MonthlyReport` type, wrong props type
   on `UsersScreen`, invalid `StyleSheet.absoluteFillObject`, unsafe error-map casts (new
   `firstFieldErrors` helper), and an unsafe union access in the period filter.
6. Default mobile API URL was a hard-coded personal LAN IP → now `10.0.2.2:5000`.
7. `.env.example` was missing `DIRECT_URL` (required by Prisma) and contained real credentials.
8. Normalised CRLF → LF line endings.

## Security — action required
The uploaded `.env` files and `.env.example` contained the **real Neon database password**.
Treat it as compromised: reset it in the Neon dashboard, and use a freshly generated
`JWT_SECRET`. Also change the seeded demo passwords.

## Existing database
This project's `init` migration now defines the column as `fuel_type`. If your Neon database
was migrated with the old history, either reset it (`npx prisma migrate reset` — deletes data)
or, to keep data: `ALTER TABLE fuel_entries RENAME COLUMN "fuelType" TO fuel_type;`, then
clear the `_prisma_migrations` table and run
`npx prisma migrate resolve --applied 20260101000000_init`.

## Round 2 — runtime audit (tested against a real PostgreSQL 16)
Bugs found by running the server and the full API suite:
1. **OCR could crash the whole API.** If Tesseract could not download its language model,
   tesseract.js re-threw the error as an uncaught exception and the server shut down. The
   English model now ships with the app (`@tesseract.js-data/eng`), worker errors are handled
   (`errorHandler`), a failed start is retried on the next request, and jobs are queued.
2. **Deactivating a driver did nothing** to the driver record (only their logins were
   disabled). `isActive` is now saved.
3. **Driver↔vehicle assignment was not atomic.** All assignment writes now run in one
   transaction (`fleet.service.ts`), and create/update share the same code path.
4. **Accountants could not verify or reject entries.** New `PATCH /api/fuel/:id/status`
   (admin, accountant) plus Verify / Reject / Set Pending buttons on the entry detail screen.
5. Entry deletion removed the slip image before the DB row; now DB first.
6. Mobile: a network error at start-up wiped the saved login token. Now only 401/403 does.
7. Mobile: photos are downscaled to 1600px JPEG before upload (faster upload and OCR).
8. Stale tests fixed (missing `/api` prefix, old response shapes, uppercase normalisation);
   new tests added in `status-and-fleet.suite.ts`.
